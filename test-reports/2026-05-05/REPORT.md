## Баги и нюансы

### 🟡 Bug #1 — profile-extraction теряет ключевое слово «пара»

**Где:** `_extract_client_profile_hint` (regex-парсинг) в `backend/app.py`.
**Симптом:** В Сц.4 я ввёл «Профиль: пара 30 лет, спокойный отдых, без анимации, премиум.» — backend сохранил `client_profile = "премиум, спокойный отдых"`. Слово **«пара» потерялось**, поэтому `_is_couple_profile` (регекс `\bпар[аое]\b|молодож|роман|медов\w*\s+месяц|вдво[её]м`) вернул `False`, и `match_couple` не повесился ни на одну карточку.

**Воспроизведение:**
1. В чате: «Это пара 30 лет, спокойный отдых, без анимации, премиум.»
2. Поиск: 5★ Анталья всё включено.
3. Ожидание: бейджи 💕 Для пары на 1-2 топовых картах.
4. Факт: только recommend_premium / recommend_optimum / recommend_budget. Бейджа 💕 нет.

**Серьёзность:** низкая — recommend-бейджи всё равно отрабатывают, агент видит лучшие варианты. Но match_couple — это product feature, которой не пользуются по факту, пока profile-extraction не сохраняет полное предложение.

**Совет на фикс:** в `_extract_client_profile_hint` вместо очистки от ключевых слов сохранять **исходную фразу** агента, или явно дописывать «пара»/«семья» в нормализованный текст.

### 🟡 Bug #2 — LLM не всегда вызывает `get_country_memo`

**Где:** системный промпт §7.x + tool definition.
**Симптом:** На запрос «Дай памятку для клиента по Таиланду — виза/валюта/советы» LLM отвечает **из своих знаний** вместо вызова tool. Endpoint работает (`GET /api/copilot/country-memos/turkey` → HTTP 200, 9.7 KB).

**Воспроизведение:**
1. Чат: «Дай памятку для клиента, едущего в Таиланд. Нужны базовые вещи: виза, валюта, советы.»
2. Ожидание: tool_call get_country_memo → реальный текст из `country_memos.json`.
3. Факт: LLM выдумывает свой ответ (часть фактов корректна, часть — устаревшая).

**Серьёзность:** низкая — UI содержит отдельную вкладку «Памятки», где данные точно из источника. Но в чатовом сценарии копайлот мог бы быть точнее.

**Совет на фикс:** либо добавить в системный промпт явное правило «при любом упоминании страны + (виза/валюта/памятка) → обязательно `get_country_memo`», либо просто принять как есть (вкладка «Памятки» решает проблему).

### 🟢 Несущественные наблюдения

1. **profile «с детьми» прилипает не туда.** В Сц.6 я явно написал «пара 30 лет, 2 взрослых без детей» — backend всё равно вытащил `с детьми`. Происходит из-за того, что в системе при первом упоминании «детей» в любой форме (даже отрицательной) regex захватывает фразу. Не блокер.
2. **BB/HB/AI всё-таки утекают в текст.** В Сц.6 при описании отеля LLM написала «BB – завтрак; HB – завтрак и обед…». Это нарушение §1 промпта (аббревиатуры — только в крайнем случае). Минорный косметический момент.
3. **Сценарий 11 — образцовый.** Длинный диалог: 5 шагов, refine на 5★ корректно вернул 0 вариантов и предложил расширить, сравнение по 6 измерениям с вердиктом, чистый WhatsApp-драфт. Это де-факто реальный рабочий день агента.
4. **Сценарий 5 — самый красивый.** Сравнение 6×6 с детальной привязкой к профилю клиента «семья 2+1, ребёнок 5 лет», вердикт с числовой разницей «доплата 21 135 ₽ оправдана для ребёнка 5 лет».
5. **Time-to-result.** Простой поиск: 15-25s. Сравнение с prefetch hotel_info: 90-110s (норма — параллельные API вызовы). Актуализация: 5s. Подборка недели: 12s.

## Что точно работает (✅)

- Каскад из 7 слотов с одним вопросом за ход + backend-страж против поиска без состава.
- Vision: парсинг скриншота, дешидрация истории с сохранением summary.
- Recommend-бейджи: 🥇 Лучший / 💎 Премиум / 💰 Дешевле появляются автоматически.
- match_family на семейном профиле (на BLUE FISH, SIMPLY FINE).
- Сравнение 1 vs 2 в формате 6×6 с конкретным вердиктом и привязкой к профилю.
- get_hotel_info — описание отеля, услуги для детей, фото.
- actualize_tour — реальный вызов и ответ «без изменений / упала / выросла».
- POST /api/collection — создание подборки с share-URL и email-вариантом.
- Аналитика просмотров share-страницы — counters работают (views, unique_views, last_viewed_at).
- get_hot_tours — горящие туры с разными странами.
- Подборка недели — quick-action собирает 5 стран и сразу делает share-URL.
- Возражение «дорого» — короткие фразы + альтернатива из last_cards.
- WhatsApp-драфт — без аббревиатур (BB/HB/AI), без ID, с CTA «бронируем?».
- Edge-case: на нереальные параметры — честный ответ «0 отелей», без галлюцинаций.
